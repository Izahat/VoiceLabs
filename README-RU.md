**VoiceLabs — это локальная AI-студия для дизайна голосов, клонирования исходных голосов и транскрипции аудио или видео.** Активные речевые модели запускаются из Python-приложения, пользовательские медиафайлы хранятся в локальной файловой системе, а метаданные рабочих процессов — в SQLite.

Интерфейс построен на обычных HTML, CSS и JavaScript без frontend-фреймворков. Он включает рабочее пространство с приоритетом тёмной темы, адаптивную мобильную версию, светлую тему, системную тему, а также локализацию на английский, русский и азербайджанский языки.

## Текущие возможности

- **Дизайн голоса** — создание речи через OmniVoice по тексту и характеристикам голоса: пол, возраст, высота, стиль, акцент и дополнительные инструкции.
- **Клонирование голоса** — загрузка аудио- или видеообразца либо запись через микрофон, создание многоразового профиля и синтез нового текста этим профилем.
- **Транскрипция** — преобразование загруженного аудио/видео или поддерживаемой публичной ссылки в полный текст и сегменты с временными метками.
- **Запись через микрофон** — удержание кнопки, запуск и остановка с клавиатуры, отдельная кнопка остановки, таймер, живая waveform и обработка ошибок микрофона.
- **Воспроизведение аудио** — waveform, запуск и пауза, перемотка, громкость, отключение звука, длительность и скачивание в реальном формате медиафайла.
- **Последние задачи** — локально сохранённая история рабочих процессов с типом, статусом, языком, временем и доступными результатами.
- **Голосовые профили** — просмотр сохранённых клонированных профилей и повторное использование профиля, если это поддерживает backend.
- **Локальное хранение** — метаданные в SQLite и аудио/видео в файловом хранилище.
- **Темы и локализация** — тёмная, светлая и системная темы; английский, русский и азербайджанский языки интерфейса.

## Статус продукта

Сейчас активны следующие рабочие процессы:

- Дизайн голоса
- Клонирование голоса
- Транскрипция аудио и видео
- Транскрипция поддерживаемых URL
- Последние задачи
- Голосовые профили

Следующие возможности пока намеренно не отображаются как активные:

- Диаризация спикеров
- Перевод
- Автоматический дубляж видео
- Оркестрация дубляжа с несколькими спикерами

## Модели

### ASR — Faster Whisper Turbo

- **Репозиторий:** `deepdml/faster-whisper-large-v3-turbo-ct2`
- **Среда выполнения:** `faster_whisper.WhisperModel`
- **Формат:** CTranslate2
- **Использование:** транскрипция и сегменты с временными метками

### TTS и клонирование голоса — OmniVoice

- **Репозиторий:** `k2-fsa/OmniVoice`
- **Среда выполнения:** `omnivoice.models.omnivoice.OmniVoice`
- **Использование:** дизайн голоса, синтез через профиль и клонированная речь

## Кэш моделей и выбор устройства

Веса моделей автоматически скачиваются при первом обращении к рабочему процессу. При последующих запусках используется локальный snapshot Hugging Face, поэтому повторная загрузка не выполняется.

### Важно: веса моделей сохраняются локально в кэше

Обе активные модели скачиваются в локальный кэш Hugging Face:

- `deepdml/faster-whisper-large-v3-turbo-ct2` — ASR и транскрипция
- `k2-fsa/OmniVoice` — TTS, дизайн голоса и клонирование голоса

Первый запрос ASR или TTS может выполняться дольше, потому что необходимые файлы модели скачиваются. После этого VoiceLabs загружает те же веса из кэша. Файлы моделей не хранятся в `README.md`, Git, SQLite, `data/storage` или пользовательских папках с медиафайлами.

Стандартные расположения кэша:

```text
Linux / WSL: ~/.cache/huggingface/hub/
Windows:     C:\Users\<user>\.cache\huggingface\hub\
```

Пользователь может указать собственное расположение моделей через `MODEL_CACHE_DIR` в `.env`:

```env
MODEL_CACHE_DIR=D:/VoiceLabs/models
```

Если `MODEL_CACHE_DIR` пустой, VoiceLabs использует стандартные расположения кэша Hugging Face, указанные выше. Если путь задан, папка создаётся автоматически, и обе модели скачиваются именно туда. После изменения настройки необходимо перезапустить backend.

Кэш содержит веса моделей, но не пользовательские аудио- и видеофайлы. У каждого компьютера свой отдельный кэш; после клонирования репозитория файлы моделей не входят в проект.

Поведение устройства:

- `DEVICE=auto` или соответствующая настройка модели выбирает CUDA, если она доступна.
- Если CUDA недоступна, runtime переключается на CPU.
- Whisper использует `float16` на CUDA и подходящий тип вычислений на CPU.
- В логах отображаются выбранное устройство, тип вычислений и путь к snapshot модели.

### Поток запроса

```text
Браузер
```

## Хранение данных и медиафайлов

Большие бинарные медиафайлы хранятся как обычные файлы. SQLite хранит метаданные и связи, а не большие аудио- и видеообъекты.

```text
data/
├── voicelabs.db
└── storage/
    └── users/
        └── <user_id>/
            └── assets/
                └── <asset_id>.<extension>

output/
├── vd_<id>.wav                  Результат runtime для дизайна голоса
├── tts_<voice_id>.wav           Результат runtime синтеза профиля
└── voice_<voice_id>/             Исходник runtime голосового профиля

tmp/
└── <рабочие каталоги задач>      Временные файлы извлечения и скачивания
```

SQLite сохраняет пользователей, задачи, пути к ассетам, исходные имена файлов, типы медиа, размеры, контрольные суммы, языки, статусы и связи с голосовыми профилями. Временное аудио, извлечённое из видео, удаляется после обработки там, где это предусмотрено рабочим процессом.

## Требования

- Python 3.10 или новее
- FFmpeg, доступный через `PATH`
- PyTorch
- NVIDIA GPU с поддержкой CUDA рекомендуется для ускорения, но предусмотрен запуск на CPU
- Доступ к сети для первой загрузки моделей
- Достаточно места на диске для snapshot моделей и локальных медиафайлов

## Быстрый запуск на Linux или WSL

Запускайте backend и frontend в отдельных терминалах.

### 1. Создание окружения

```bash
git clone https://github.com/Izahat/VoiceLabs.git
cd VoiceLabs
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Если нужна CUDA-версия PyTorch, установите сборку, совместимую с вашим драйвером, до установки остальных зависимостей.

### 2. Запуск API

```bash
source venv/bin/activate
python main.py
```

FastAPI работает по адресу:

```text
http://localhost:8000
```

Документация API доступна по адресу:

```text
http://localhost:8000/docs
```

### 3. Запуск frontend

Рекомендуемый локальный static-сервер:

```bash
python -m http.server 4173 --directory frontend
```

Откройте:

```text
http://localhost:4173/?v=11#design
```

Frontend обращается к API по адресу `http://localhost:8000/api/v1`.

### Дополнительный proxy-сервер

`proxy.py` работает на порту `5173` и отдаёт frontend при запуске из корня проекта:

```bash
python proxy.py
```

Открывайте соответствующий порт:

```text
http://localhost:5173/?v=11#design
```

Не смешивайте URL `4173` с `proxy.py`: эти локальные серверы используют разные порты.


## Активный API

### Транскрипция

- `GET /api/v1/transcription/health`
- `POST /api/v1/transcription/transcribe` — загрузка аудио или видео
- `POST /api/v1/transcription/transcribe/url` — скачивание поддерживаемого URL и ASR
- `GET /api/v1/transcription/supported-platforms`

Ответы ASR содержат определённый или выбранный язык, полный текст, длительность и сегменты с временными метками. Диаризация спикеров не активна.

### OmniVoice

- `POST /api/v1/dubbing/tts/voice-design` — генерация речи по характеристикам голоса
- `POST /api/v1/dubbing/tts/clone` — подготовка голосового профиля из аудио или видео
- `POST /api/v1/dubbing/tts/synthesize` — синтез текста сохранённым профилем
- `GET /api/v1/dubbing/languages`
- `GET /api/v1/dubbing/voices`

### Сохранение и ассеты

- `GET /api/v1/dubbing/jobs` — история текущего локального пользователя
- `GET /api/v1/dubbing/status/{job_id}` — статус задачи
- `GET /api/v1/dubbing/voice-profiles` — сохранённые голосовые профили
- `GET /api/v1/dubbing/assets/{asset_id}` — сохранённый медиафайл

Браузер создаёт локальный `X-User-Id` и сохраняет его в `localStorage`. Это идентификатор локального рабочего пространства, а не полноценная production-аутентификация.

## Дизайн-система frontend

Визуальным источником истины является [`design.md`](design.md). Реализация использует:

- графитовые поверхности и иерархию с приоритетом тёмной темы;
- сдержанный фиолетовый/лавандовый акцент;
- переиспользуемые CSS-переменные для цвета, отступов, радиусов, фокуса, высоты и анимаций;
- Lucide-подобные иконки из `frontend/assets/lucide-sprite.svg`;
- общие шаблоны рабочих областей, форм, dropzone, рекордера, плеера, результатов, модальных окон и статусов;
- одноколоночные рабочие процессы на мобильных устройствах;
- доступные подписи, live-регионы, клавиатурное управление, focus-visible и поддержку уменьшенной анимации.

Сгенерированный фоновый ассет находится в `frontend/assets/voicelabs-ambient-bg.png` и намеренно имеет низкую контрастность за поверхностями рабочего пространства.

## Тестирование и проверка

Запускайте доступные Python-проверки из корня проекта:

```bash
python -m unittest discover -s tests -v
python -m compileall app config infrastructure providers main.py
```

Для ручной smoke-проверки:

1. Запустите `main.py` и убедитесь, что открывается `http://localhost:8000/docs`.
2. Запустите frontend на `4173` или используйте `proxy.py` на `5173`.
3. Проверьте навигацию, темы, языки, загрузку файлов, запись через микрофон, воспроизведение, транскрипцию, клонирование и скачивание.
4. Убедитесь, что первый запрос к модели скачивает веса, а следующие запросы используют кэш.

## Приватность и безопасность

VoiceLabs спроектирован как локальное приложение. Пользовательские медиафайлы и запуск моделей остаются в настроенной локальной среде, если будущая функция явно не подключит внешний провайдер.

Перед публикацией сервиса за пределами доверенного компьютера добавьте полноценную аутентификацию, авторизацию, подписанные URL ассетов, проверку загрузок, ограничение частоты запросов, безопасное управление секретами и production-стратегию для базы данных и хранилища.
